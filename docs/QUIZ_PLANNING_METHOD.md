# 문제 제작 방법 (모든 과목 공통 지시서)

> AI가 어떤 과목이든 시험 대비 문제 세트를 만들 때 **반드시 이 순서**를 따른다.
> 2026-10-30 사용자 지시("어떤 과목이던 유형 분류 + 제작 순서, 제작 체계, 족보 선지 분석을 뽑아 계획한 뒤 진행")를 정형화한 문서.
> 실제 적용 예: `ORGCHEM_FINAL_PLAN.md`(반응 과목), `BIOCHEM_FINAL_PLAN.md`(개념·서술 과목), `PHARMACOGNOSY_FINAL_PLAN.md`(암기 과목).

## 0. 시작 전 확인
1. `ls -lt ~/study_system/materials/<과목>/` — 자료는 2026-11-09부터 이 폴더에 있다. 계획서 등 옛 문서의 `materials/...` 경로도 `~/study_system/materials/...`로 읽는다. 사용자가 말없이 새 자료(PPT·족보·문제집)를 넣었을 수 있다. **가장 먼저** 확인한다.
2. 작업 브랜치 확인(학기·시험별 브랜치, 예: `2026-2-final`). main에는 앱 코드만 둔다.
3. 이미 계획서(`docs/<과목>_FINAL_PLAN.md` 등)가 있으면 "진행 상황"부터 읽고 이어서 한다.

## 1. 바로 만들지 말고 계획서를 먼저 쓴다
계획서 파일: `docs/<과목>_<시험>_PLAN.md`. 아래 장을 모두 채운 뒤 **사용자에게 요약과 예시를 보여 주고 승인받는다.** 승인 전에는 덱을 만들지 않는다.

### 1-1. 범위와 자료
- 시험 범위(수업 계획표·사진 등)를 단원·주차·항목 목록으로 확정한다.
- 자료마다 **종류와 상태**를 적는다: 교재(텍스트/스캔), 요약집, 강의 PPT, 족보(연도·원본/복원·답 유무), 문제집.
- 자료 우선순위를 정한다. 사용자가 정해 준 기준이 있으면 그대로 따른다(예: 생약학 = 요약집 + 족보 기본, 교재는 빈칸 채우기).

### 1-2. 족보 분석
1. 연도별 **형식**(문항 수, 객관식/주관식/서술형, 묶음 보기)과 그 변화.
2. **문항 유형 분류표**: 코드 · 유형 이름 · 족보 실례(연도-번호) · 빈도. 빠짐없이, 범위의 특수 유형까지. 족보에 없지만 나올 만한 유형은 "제안"으로 따로 표시한다.
3. **반복 출제 목록**: 여러 해에 나온 항목은 최우선으로 다룬다.
4. 개념 문제는 **보기 하나하나가 무엇을 묻는지(축)** 분해한다(2장).

### 1-3. 제작 순서
- 단계표: 단계 · 내용 · 형식 · 대략 문항 수. **세트(덱) 하나는 30문항 이하.**
- 기본 흐름: 기초 사실·용어 → 짝 맞추기·드릴 → 비교·묶음 → 개념 진술(함정 선지) → 응용·종합 → 족보 실전.
  사용자가 순서를 정해 주면 그 순서를 따른다.
- 과목 성격별 첫 단계
  | 과목 성격 | 첫 단계 |
  |---|---|
  | 반응·구조(유기화학) | 반응 목록 → 생성물 문제 |
  | 개념·서술(생화학) | 용어·구조 → 개념 진술 → 서술 키워드 |
  | 암기 항목이 많은(생약학 등) | **항목별 카드(데이터) → 카드 자체로 문제** → 유형별 드릴 |

### 1-4. 오답 제작 체계 (2장 요약을 과목에 맞게 적는다)
### 1-5. 예시 1개
족보 문항 하나(aa)를 축으로 분해하고, **같은 축으로 다른 주제(bb)** 문항을 만든 표를 보여 준다(옳은 문장 / 틀린 문장 / 쓴 왜곡 기법).
### 1-6. 사용자에게 받을 것·물을 것
빠진 자료(PPT·문제집·녹음), 범위 애매한 곳, 사용자가 골라야 할 선택지(추천 표시).

## 2. 오답 제작 체계 (공통)
> 2026-10-30 사용자 지적: "정답 선지는 잘 만들고 오답은 대충 만든다, 너무 AI스럽다." → 오답에 더 공을 들인다.

### 2-1. 개념 진술(옳은/틀린 것 고르기): 축 → 개념어 교체 → 왜곡 기법
1. 족보 문항의 5개 보기를 **축**(보기마다 묻는 개념 차원)으로 분해한다.
2. 새 주제로 옮길 때 축마다 들어갈 개념어를 표로 채운다. 맞지 않는 축은 그 주제 고유의 축으로 바꾼다.
3. 축마다 **옳은 문장 / 틀린 문장 쌍**을 만든다. 틀린 문장은 아래 기법 중 하나로만 만든다.

| 기법 | 내용 |
|---|---|
| T1 반의어 뒤집기 | 증가↔감소, 짝산↔짝염기, 발한↔지한 |
| T2 필요조건 부정 | "반드시 ~하지 않아도 된다" |
| T3 전칭 과장 | "항상", "모두", "예외 없이" |
| T4 그럴듯한 틀린 인과 | 맞는 사실 + 틀린 이유 |
| T5 가능↔불가능 뒤집기 | "~할 수 없다" |
| T6 수치·범위 바꾸기 | 함량·pKa·순서·개수 |
| T7 사례 바꿔치기 | 맞는 원리 + 틀린 사례(비슷한 다른 항목과 맞바꾸기) |

4. 조립 규칙: 5개 보기는 **서로 다른 축**. 길이·말투를 비슷하게(정답이 가장 길거나 자세하지 않게). 틀린 문장은 "앞은 맞고 뒤(이유·조건)만 틀린" 형태가 기본.

### 2-2. 짧은 답(이름·성분·구조) 보기: "헷갈리는 이웃"에서 고른다
- 무작위 오답 금지. 오답은 **실제로 헷갈릴 이유가 있는 것**만: 같은 분류(같은 과·계열·반응 종류), 이름·철자가 비슷한 것, 짝을 이루는 것(동류·관련 항목), 한 단계 덜/더 간 것, 반대 방향.
- 과목별로 **오답 코드표**를 계획서에 적는다(예: 유기화학 X1~X7, 생약학 "이웃 규칙표").

### 2-3. 해설
- 정답 근거 + **오답마다 어떤 오개념을 노렸는지** 적는다.
- 개념 진술은 5개 보기를 모두 설명한다.
- 여러 단계(1) 2) 시약 등)는 중간 과정을 단계별로 보여 준다.

## 3. 덱 작성 규칙
- 형식은 `CLAUDE.md`의 "퀴즈 형식"을 따른다. 덱 글에 `**`(굵게) 쓰지 않는다(앱이 그대로 보여 줌). 줄바꿈 `\n`은 표시된다.
- 족보·외부 답안 덱에는 **작성자 이름·학번을 넣지 않는다**("외부 답안"으로만). 족보 그림의 이름 워터마크는 지우고 쓴다.
- 족보 복원이 불완전해서 고친 문항은 "재구성" 표시를 한다. 답이 불확실하면 ⚠ 표시와 근거를 적는다.
- 사실 확인은 교재·요약집·PPT로 한다. 문제 사이트는 유형만 참고하고 문제를 베끼지 않는다.
- 구조식 SMILES는 RDKit로 검사하고, 앱 스크린샷으로 한 번 확인한다.
- 보조 스크립트는 저장소 밖 `../.tools/`에 둔다(scratchpad는 매일 지워짐).
- 기존 덱을 고칠 때 문제 `id`는 유지한다.
- 단계마다 `.github/scripts/check_decks.py`로 검사 → 커밋 → **묻지 않고 push**(Pages 반영).

- 한국어, 초보자도 이해하게. 표로 요약.

- 제작 단계: 만든 덱·문항 수, 앱에서 확인하는 방법(어느 과목 → 어느 덱), 다음 단계.
