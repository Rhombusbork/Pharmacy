# AI 퀴즈 생성 프롬프트 템플릿

새 퀴즈 덱이 필요할 때 아래 **"복사할 프롬프트"** 부분을 통째로 복사해서 AI(Claude, ChatGPT 등)에게 붙여넣으세요.
`[대괄호]` 부분만 내 상황에 맞게 바꾸면 됩니다.

## 사용 순서

1. 아래 프롬프트의 `[대괄호]`를 채운다.
2. 맨 아래 "공부 내용" 자리에 강의 노트·교재 내용을 붙여넣는다.
3. AI가 준 JSON을 `decks/<과목폴더>/<파일명>.json`으로 저장한다.
4. `decks/index.json`의 `"decks"` 목록에 경로를 한 줄 추가한다. (앞 줄 끝에 쉼표 `,` 잊지 않기)
5. 앱을 새로고침해서 경고가 없는지 확인한다.

## 이미 쓰고 있는 과목·deckId (겹치지 않게!)

| 과목 | 폴더 | deckId 예 |
|---|---|---|
| 생화학 | `biochem/` | `biochem-01` |
| 생약학 | `pharmacognosy/` | `pharmacognosy-01` |
| 유기화학 | `orgchem/` | `orgchem-01` |
| 분석화학 | `analchem/` | `analchem-01` |
| 물리약학 | `physpharm/` | `physpharm-01` |

같은 과목의 다음 덱은 번호만 올리면 됩니다. 예: `biochem-02`
새 덱을 만들면 이 표에도 적어 두면 편합니다.

## 복사할 프롬프트

````
아래 공부 내용으로 퀴즈를 만들어 줘. 반드시 아래 JSON 형식과 규칙을 지켜야 해.

[덱 정보]
- deckId: [예: biochem-02]
- subject: [예: 생화학]   ← 과목명은 기존과 글자까지 똑같이
- title: [예: 2차시: 효소]
- 문제 수: [예: 15]
- 객관식:주관식 비율: [예: 7:3]

[JSON 형식]
{
  "deckId": "biochem-02",
  "subject": "생화학",
  "title": "2차시: 효소",
  "questions": [
    {
      "id": 1,
      "question": "효소 반응 속도가 최대 속도의 절반일 때의 기질 농도를 무엇이라 하는가?",
      "choices": ["Km", "Vmax", "kcat", "Ki"],
      "answer": "Km",
      "explanation": "미카엘리스 상수 Km은 v = Vmax/2 일 때의 기질 농도이다."
    },
    {
      "id": 2,
      "question": "효소의 활성 부위에 기질과 경쟁적으로 결합하는 저해 방식은?",
      "answer": ["경쟁적 저해", "competitive inhibition"]
    }
  ]
}

[규칙]
1. deckId, subject, title, questions 는 모두 필수.
2. id 는 1부터 시작하는 정수이며 덱 안에서 겹치면 안 된다.
3. question 과 answer 는 필수이며 빈 값이면 안 된다.
4. 객관식은 "choices"(문자열 배열, 2~6개)를 넣는다.
   - answer 는 문자열 하나이며, choices 중 하나와 띄어쓰기·기호까지 정확히 같아야 한다.
   - 정답이 항상 같은 위치에 오지 않게 한다. (앱이 선지를 섞긴 하지만 그래도 골고루)
   - "모두 정답", "정답 없음" 같은 선지는 쓰지 않는다.
5. 주관식은 "choices"를 넣지 않는다.
   - answer 는 문자열 하나, 또는 여러 표현을 정답으로 인정하려면 문자열 배열.
   - 한글 이름, 영문 이름, 약어, 흔한 다른 표기를 배열에 함께 넣는다. 예: ["펩타이드 결합", "펩티드 결합", "peptide bond"]
   - 답이 한두 단어로 딱 떨어지는 문제만 주관식으로 낸다. (문장형 서술 답 금지)
   - 대소문자와 띄어쓰기는 앱이 무시하므로, 그것만 다른 표기는 따로 넣지 않아도 된다.
6. explanation(해설)은 선택이지만, 헷갈리기 쉬운 문제에는 1~2문장으로 넣는다.
7. "type" 필드는 쓰지 않는다.
8. 공부 내용에 없는 사실을 지어내지 않는다.
9. 출력은 JSON 하나만. 설명 문장이나 ``` 코드 블록 표시 없이 { 로 시작해서 } 로 끝나게.
10. (구조식이 필요한 과목만) 분자 구조를 보여줄 때는 문자열 안에 [[smi:SMILES]] 를 넣는다.
   - question, choices 의 각 항목, explanation 어디에나 쓸 수 있다. 예: "다음 화합물의 이름은? [[smi:c1ccccc1O]]"
   - 구조식을 선지로 쓸 때는 answer 도 해당 선지와 글자까지 똑같이 쓴다. 예: "answer": "[[smi:CC(=O)O]]"
   - 주관식 answer 에는 구조식을 넣지 않고 이름·기호로 쓴다.
   - 반드시 표준 SMILES 를 쓴다. 입체화학은 @, @@, /, \ 로 표시한다. 확신이 없는 구조는 넣지 않는다.
   - 한 문제의 구조식은 3~4개 이하로 한다.
11. (반응이 필요한 과목만) 반응식은 [[rxn:반응물>>생성물|화살표 위|화살표 아래]] 로 쓴다.
   - 예: "[[rxn:C=CC>>CC(Br)C|HBr|CH₂Cl₂, 0 °C]]"
   - 반응물·생성물이 여럿이면 . 으로 잇는다. 시약·조건은 SMILES가 아니라 화살표 위·아래 글자로 쓴다.
   - 시약을 묻는 문제는 화살표 위를 ? 로 둔다. 예: "[[rxn:CC(=C)C>>CC(C)(C)O|?]]"
   - 화학식의 아래 첨자는 ₂ ₃ 같은 문자로 쓴다. 예: H₂SO₄
   - 전자 이동(굽은) 화살표나 반응 메커니즘 그림은 만들지 않는다.

[공부 내용]
[여기에 강의 노트나 교재 내용을 붙여넣기]
````

## 자주 생기는 실수

- **객관식 answer가 선지와 글자가 다름**: 예: 선지는 `"시스테인"`인데 answer가 `"시스테인 (Cys)"`. 앱이 이 문제를 제외합니다.
- **반응식 오류**: `>>`가 빠졌거나 반응물·생성물 SMILES가 틀리면 `반응식 해석 실패` 경고가 뜹니다.
- **SMILES 오타**: 홈에 `SMILES 해석 실패: ...` 경고가 뜨고 그 문제는 제외됩니다. 괄호·고리 번호 짝이 맞는지 확인하세요. 해석은 되지만 **다른 분자**를 그리는 실수는 검사기가 못 잡으니, 그림을 눈으로 한 번 확인하세요.
- **deckId 중복**: 다른 덱과 같은 deckId면 기록이 섞이므로 앱이 경고합니다.
- **index.json 쉼표 누락**: 목록 마지막 줄을 뺀 모든 줄 끝에 쉼표가 있어야 합니다.
- **이미 쓰는 덱을 고칠 때**: 문제 문장이나 선지는 고쳐도 되지만 `id`와 `deckId`는 절대 바꾸지 마세요. 바꾸면 그 문제의 풀이 기록이 끊깁니다. 새 문제는 기존 마지막 id 다음 번호로 추가하세요.
